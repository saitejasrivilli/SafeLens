# Evaluation — Phase 3 Baseline

All numbers below come from `benchmarks/results/baseline/experiment.json`, generated by
`scripts/train_baseline.py` (`make baseline-train`). Measured locally on Apple M2. Not
production-scale, not comparable to full-corpus results.

## Metrics computed

Accuracy, precision, recall, F1, macro F1, PR-AUC, ROC-AUC, false-positive rate,
false-negative rate, confusion matrix, positive-prediction rate. **Accuracy is not the
headline metric** — at a 5% positive rate, a model that predicts "not toxic" for everything
scores ~95% accuracy while being useless for moderation. Precision/recall/PR-AUC and the
false-negative rate (missed toxic content) are the metrics that matter here.

## Threshold selection

**Criterion:** maximize F1 on the validation set (config: `decision_threshold.selection_metric: f1`).
**Selected threshold: 0.5** — validation F1 0.362, the maximum across all 9 candidates.
Selected and frozen using validation data only; the test set was not touched until after
this selection (`scripts/train_baseline.py`, test set evaluated exactly once, after the
threshold is fixed).

Note the sweep shows the standard precision/recall tradeoff: low thresholds catch nearly
all toxic comments (recall 1.0 at 0.1) at the cost of an unusable 97% false-positive rate;
high thresholds are precise but miss almost everything (recall 0.016 at 0.9). 0.5 is the
best F1 balance point for this baseline, not necessarily the right operating point for a
real moderation policy — that tradeoff (cost of a missed violation vs. cost of a false
block) is a Phase 10 policy-engine decision, not a Phase 3 modeling decision.

## Training time / inference performance (measured locally on Apple M2)

- Training time (TF-IDF fit + transform + Logistic Regression fit): **0.65s** on 5,588
  training examples.
- Inference: `model.predict_proba` on the already-vectorized test set (1,197 examples) —
  **~5.98M examples/sec, ~0.00017ms/example**. This measures only the Logistic Regression
  forward pass, not TF-IDF vectorization time, and reflects the trivial cost of a linear
  model on a small test set — not a representative production throughput number.

## Reproducibility

The full pipeline was run twice end-to-end (same dataset manifest, same config, same
seed=42). All threshold-sweep values, selected threshold, validation metrics, test metrics,
and artifact hashes were bit-identical between runs; only wall-clock timing fields differed.

## Limitations

- PR-AUC 0.27 / test F1 0.28 reflect a genuinely hard problem at this data scale (61
  positive examples in the test set) and a bag-of-n-grams model — not a bug. This is the
  number Phase 4 (DeBERTa) should be compared against honestly, not something to improve by
  changing Phase 3's methodology after the fact.
- Metrics are only for `toxicity`; the other 6 dataset dimensions are unevaluated (Phase 3
  scope, see `docs/model_design.md`).
